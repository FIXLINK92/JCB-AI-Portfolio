# Recruiter Guide — 5-Minute Review

This repository is intentionally structured so a recruiter or technical manager can evaluate it quickly without access to the private production repositories.

## 1. Start with the evidence matrix

Open [`SKILLS_EVIDENCE_MATRIX.md`](SKILLS_EVIDENCE_MATRIX.md). It separates capabilities into:

- **Demonstrated** — supported by project work or validation evidence.
- **Working knowledge / developing** — understood and being expanded, but not represented as deep production mastery.
- **Not claimed** — not presented as experience merely because related tools appear in a job description.

## 2. Review the strongest project for the role

For AI/full-stack/automation roles, start with:

- [`projects/luxorium-control-plane.md`](projects/luxorium-control-plane.md) for full-stack, API, database, authentication and test architecture.
- [`projects/ai-hq.md`](projects/ai-hq.md) for AI-assisted engineering process, CI and development controls.

For operational digitization / mobile workflow roles:

- [`projects/armored-vehicle-qc.md`](projects/armored-vehicle-qc.md)

For data/analytics roles:

- [`projects/real-estate-analytics.md`](projects/real-estate-analytics.md)

## 3. Check architecture

Each project has a simplified Mermaid diagram in [`architecture/`](architecture/). These are intentionally high-level and safe for external review.

## 4. Check code samples

[`code-samples/`](code-samples/) contains synthetic examples written specifically for portfolio demonstration. They are not presented as copied production source.

## 5. Request a live walkthrough

A live walkthrough can cover:

- the private project UI running locally,
- the project workflow and architecture,
- test evidence,
- how a scoped change moves from requirement to validation,
- troubleshooting approach.

Private source access is not required for a first-stage evaluation.
